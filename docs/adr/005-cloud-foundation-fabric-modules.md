# 005 — Cloud Foundation Fabric modules for geap-agent-secured
**Date:** 2026-10-09 | **Status:** accepted

## Context
`geap-agent-secured` is written with raw `google_*` resources: no `terraform-google-modules` module covers Agent Gateway or Agent Runtime. Cloud Foundation Fabric publishes `geap-agent-gateway` and `geap-agent-runtime`, plus `gcs`, `cloud-function-v2` and `iam-service-account`. A second attempt at the secured sample (code execution sandbox never completing its creation operation on the gateway-bound engine) uses them, side by side with the original.

Fabric is not on the Terraform Registry: modules are sourced from GitHub. Release `v59.0.0` sets `dns_peering_config.domain` on the connectivity template, which the `google` 8.5 provider rejects; commit `ccd4c1c95` (2026-10-06) fixes it, and no tag contains it yet.

## Decision
`samples/geap-agent-secured` uses the Fabric modules wherever one exists, all pinned to the same commit SHA of `master` (`25d8d9a0ca869fd15083a16183f61de1408524e3`, 2026-10-09): an immutable reference, moved to the next release tag once it contains the fix. Raw resources remain where Fabric has no module or cannot take the value at plan time:

- Agent Registry services, Model Armor templates (the gateway module takes their ids), the network attachment;
- the per-endpoint `roles/iap.egressor` grants: the module infers the binding type from which id is set, and an endpoint id generated by Agent Registry leaves its `for_each` keys unknown at plan (its whole-registry alternative would open the endpoints of the other samples).

The network attachment is passed to the gateway module through `context` (`$psc_network_attachments:egress`), so that the module counts its connectivity template on a value known at plan time.

## Consequences
- Git-sourced modules are an explicit exception to the "registry-only" rule, requested for this sample; the SHA pin keeps builds reproducible. `terraform init` needs access to github.com.
- The gateway module configures its own provider (`networkservices` v1alpha1 endpoint): provider `default_labels` do not reach its resources (labels passed explicitly, authz resources unlabelled), the module cannot be used with `depends_on`/`count`/`for_each`, and `mock_provider` does not reach it: the offline tests replace it with `override_module`, or they would call the real API.
- The module does not replace the connectivity template before destroying the old one, and the API refuses to update or delete a template referenced by a gateway: changing the egress networking settings needs a detach step (see the sample README).
- Agent Runtime allows a single pair of gateways per project and region: running both secured samples side by side relies on the API accepting a second pair (verified at deployment, see `docs/VERIFICATION.md`).
- IAM bindings shared with `geap-agent-secured` (CMEK grants of the Cloud Functions and Cloud Run service agents) moved to `samples/base`, which owns the key.
